# Приложение «Строительная карьера»

Локальная демонстрация, этапы A, B1, B2 и C. React 19.3 + TypeScript 6.0.3 + Vite 8.3.4. Проверено с Node.js 24.21.0 / npm 10.9.2 на Windows. Используйте Node.js 24 LTS; версии зависимостей закреплены в package-lock.json. TypeScript 6 выбран по совместимости с typescript-eslint.

Из корня комплекта в PowerShell:

```powershell
cd app
npm.cmd ci
npm.cmd run dev
```

Открыть http://127.0.0.1:5173/#/student . Выбор роли: http://127.0.0.1:5173/#/demo . Vite сообщит другой порт, если стандартный занят.

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

Preview: http://127.0.0.1:4173/#/student . Сборка находится в `app/dist`; её следует открывать через HTTP-сервер, а не двойным щелчком по HTML. Для остановки сервера — Ctrl+C.

Браузерная проверка (при работающем dev-сервере на 5173):

```powershell
npm.cmd run test:browser
npm.cmd run test:b1
npm.cmd run test:b2
```

Используется установленный Microsoft Edge в headless-режиме. Скрипт проверяет роли, сохранение/сброс, ошибки хранилища, неизвестный адрес, возврат, конфликт вкладок, клавиатуру диалога и ширину 360 px. Он использует отдельный временный браузерный контекст и сохраняет изображения в `docs/previews`.

Работает: S01 Анны, четыре роли, сохранение самоописания отдельно от образования, рекомендации по правилам, D01/D02/D03, hash-переходы, восстановление исходного набора. Данные сохраняются в одном ключе `stroitelnaia-kariera:demo:v1`. При ошибке запись не объявляется успешной; текущее действие остаётся в памяти. Повреждённое или неизвестное сохранение не перезаписывается до подтверждённого сброса. Чужие ключи не удаляются.

B1 работает локально: публичная главная и поиск практик/работы, фильтры в адресе, карточки компаний и предложений, избранное и сохранённые поиски, образовательные исправления с решением координатора и историей, собственные учебные проекты, версии резюме, сценарный помощник с четырьмя траекториями и взвешенный подбор с источниками и unknown/coverage. Отклик сохраняет снимок выбранной версии резюме, образования и проектов; он виден студенту и работодателю своей компании. Исправление образования не меняет старый снимок. После действия появляются локальные уведомления. Старые сохранения A совместимы; данные B1 добавляются к тому же envelope, исходный seed не перезаписывается.

Все данные вымышленные. МГСУ — учебный контекст. Нет backend, регистрации, внешних отправок, реальной модели, подписи и платных услуг. Сайт не опубликован.

Для согласования: [настольный S01](../docs/previews/s01-desktop.png), [мобильный S01](../docs/previews/s01-mobile.png). Изображения поиска: [настольный P02](../docs/previews/p02-desktop.png), [мобильный P02](../docs/previews/p02-mobile.png). B2 реализован: отбор и принятие предложения, резерв/отмена, документы по версиям, согласование, задания, отчёт/отзыв и итог. Проверены SC01/SC02/SC05/SC06. Этап C реализован; следующий этап — D, полный аудит устойчивости и доступности.

Маршруты для проверки B1: `/#/` — публичная главная, `/#/practices` — практики, `/#/jobs` — работа и стажировки, `/#/student/education` — учебные сведения/запрос исправления, `/#/student/resumes` — резюме и помощник, `/#/notifications` — уведомления. Координатор рассматривает исправления в своём кабинете, работодатель видит полученные отклики. Проверки компании и модерация предложений оператором работают локально. Импорт, расширенные справочники и аналитика реализованы локально в C.

`test:b1` проходит SC01 до отправки отклика/просмотра работодателем, SC03 и SC04, проверяет AC02 и AC06–AC08, сохранение снимков и ширину 360 px. Для проверки собранной версии запустите preview в отдельном терминале и выполните:

```powershell
$env:DEMO_BASE_URL = 'http://127.0.0.1:4173/'
npm.cmd run test:b1
npm.cmd run test:b2
Remove-Item Env:DEMO_BASE_URL
```

Редакторы профиля, собственного проекта и резюме сохраняют изменения по явной кнопке; ответы, шаг и предварительный текст помощника сохраняются по ходу диалога. Исходные учебные проекты доступны только для чтения, собственное описание создаётся отдельно.

B2: на отклике работодатель выбирает этап с комментарием. Студент принимает предложение, и для практики создаётся одно дело с резервом. До отправки в вуз заполните примечание, сформируйте три обязательных документа и направьте их версии на проверку. Договор сначала проверяет компания, затем вуз; остальные начальные документы — вуз. После возврата исправьте условия, сформируйте и направьте новые версии. Вуз согласует дело, меняет учебную дату по подтверждённому демо-действию и подтверждает начало. Компания выдаёт задания и принимает результат. Студент готовит/направляет отчёт, компания оставляет отзыв, координатор проверяет новую версию и фиксирует зачёт либо завершение без зачёта.

Документы скачиваются как самостоятельные `.html` с правильным именем и кириллицей; файл можно открыть в браузере, распечатать и сохранить в PDF. Кнопка печати выводит только выбранную учебную версию. HTML не называется DOCX/PDF. Все четыре вида документов помечены учебным образцом; действий электронной подписи нет. Бинарные файлы не сохраняются в localStorage.

Новые маршруты: `/#/student/practices`, `/#/employer/practices`, `/#/employer/interns`, `/#/university/approvals`, `/#/operator/offers`, `/#/operator/organizations`. Приглашения видны в откликах студента. Диалоги открываются только в существующем отклике или разрешённом деле; до принятия приглашения свободного чата нет.

В тех же четырёх ролях доступны дополнительные вымышленные студенты Илья, Мария и Вера для проверки исходных учебных дел и ограничения мест. Главный путь — Анна; Мария позволяет показать уже подготовленную проверку отчёта. Сведения разных студентов и их самоописания разделены.

```powershell
npm.cmd run test:b2
```

`test:b2` использует Edge, отдельные временные контексты и `DEMO_BASE_URL` аналогично `test:b1`. Проверены полный SC02 с возвратами задания/документов/отчёта, SC05 и SC06, сохранение даты/итога, разрешённые сообщения, уникальный счётчик зачёта и открытие фактически скачанного файла. Результат скачивания лежит в игнорируемой папке `app/test-results`; изображения — [настольное дело](../docs/previews/b2-practice-desktop.png) и [мобильное дело](../docs/previews/b2-practice-mobile.png).

Если стандартный порт занят, используйте напечатанный Vite адрес или `npm.cmd run dev -- --port 5174` и установите `DEMO_BASE_URL` для браузерных проверок. В B2 данные добавляются как `changes.b2` к прежнему ключу; сохранения A/B1 не требуют сброса. Учебная дата сохраняется и не берётся автоматически из настоящего времени.

C работает локально: публичные каталоги/справка, подроли и назначения команды, запросы мест, описание/программы вуза, версии требований/шаблонов, тестовый JSON-импорт, обращения и ответы, справочники, контент, оценка сценарных примеров, отключение тестовых пользователей, настройки, аналитика и CSV текущей выборки. Применённые действия сохраняются в `changes.c` того же хранилища. Сброс общий, подтверждаемый; прежние сохранения совместимы.

Операторские интеграции — **симуляция без сетевых запросов**. Импорт ограничен учебным JSON `demoOnly: true`, 100 KiB / 100 строк; реальные данные вводить нельзя. Новые дела фиксируют версии требований/шаблонов, старые документы не меняются. CSV содержит агрегаты с пометкой демо, без имён, оценок и текста документов.

Маршрут C: координатор → `/#/university/company-requests` → компания `/#/employer/university-requests` → координатор `/#/university/requirements`, `/#/university/templates`, `/#/university/import`. Поддержка: `/#/support`; оператор: `/#/operator/appeals`, `/#/operator/dictionaries`, `/#/operator/reports`, `/#/operator/integrations`. Основной работодатель настраивает сотрудников в `/#/employer/team`; их можно выбрать в том же переключателе ролей.

## ИИ-помощник и Netlify Functions

См. [подробную инструкцию](../docs/gigachat-integration.md): аудит, файлы, env, Netlify и ручная проверка. Base directory Netlify — app; build/publish сохраняются. Браузерная AI-проверка: запустите dev в mock на порту 5190 и выполните npm.cmd run test:ai; при другом порте задайте DEMO_BASE_URL. Без credentials live показывает недоступность, остальные сценарии работают.
