# Инструкции для Codex: «Строительная карьера»

## Источники и приоритет

1. Последнее прямое решение заказчика в текущей задаче.
2. `docs/demo-scope.md` и утверждённые решения в `docs/decisions.md`.
3. Остальные файлы `docs/` — конкретизация демонстрации; рабочие допущения не выдавать за согласованные пожелания.
4. `source/original-spec.md` — полная целевая концепция, а не объём промышленной разработки сейчас.

При первом запуске прочитай README, scope, decisions, screens, scenarios, design, architecture и progress. Для изменяемого модуля также прочитай соответствующий специализированный документ и acceptance. Существенный конфликт зафиксируй, не исправляй требования молча.

## Результат

Адаптивная русскоязычная демонстрация со связанными действиями и моковыми данными. Без backend, реальной авторизации, реальных интеграций, LLM, подписи или платных услуг. Студенты только МГСУ. Четыре тестовые роли; переключение ролей сохраняет общий локальный сценарий. Публичный QR-вход без регистрации.

## Рабочий подход

- Сначала изучи существующие файлы. Не запускай генератор поверх содержимого с перезаписью.
- Рабочий стек: React + TypeScript + Vite. Зависимости и версии проверяй при установке; фиксируй lockfile. Если проект уже имеет подходящий стек, сначала оцени его, не пересоздавай автоматически.
- Работай вертикальными сценариями: действие → изменение общей сущности → отображение другой роли → уведомление → сохранение после перезагрузки.
- Не создавай отдельный несвязанный набор моков на каждой странице. Все экраны используют единое хранилище и доменные операции.
- Сначала создай S01 с характерными компонентами для согласования дизайна. До согласования разрешены каркас, модель, данные и логика; массовое оформление остальных экранов отложи.
- Имитируемые возможности помечай в интерфейсе. Образовательные данные и компании вымышленные. Нельзя писать, что есть реальный обмен с МГСУ или реальный ответ ИИ.
- Сохраняй основные действия и состояния из карты. 80 идентификаторов — логические представления, не требование создать 80 отдельных страниц или компонентов.
- Все кнопки должны выполнять показанное действие. Если функция вне объёма демо, объясни это рядом и не изображай успешное выполнение.
- Не добавляй оплату, внешние отправки, внешнюю аналитику, реальные персональные данные, облачную БД и секреты в клиент.
- Не публикуй репозиторий и не подключай платные услуги без отдельного поручения. Локальная сборка и проверка разрешены задачей разработки.
- Не уничтожай чужие изменения, не делай force push и не выполняй разрушительный сброс репозитория.

## Проверка и продолжение

Добавь проектные команды `dev`, `build`, `preview`, `typecheck`, `lint`, `test` по мере создания соответствующей конфигурации. Не заявляй, что команда работает, пока не выполнил её. Напиши небольшое число тестов для переходов практики, ограничений мест, подбора, сохранения и ключевого сквозного сценария; не покрывай тестами простое наличие текста.

После этапа обнови `docs/progress.md`: что реализовано, что проверено (с результатом), что осталось, какие решения приняты. Отчёт пользователю: результат, способ посмотреть, проверки, существенные ограничения. Перед сменой сеанса оставь точное следующее действие.
