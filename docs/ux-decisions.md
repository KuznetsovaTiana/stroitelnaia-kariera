# Решения по UX · 15.10.2026

Основание: прямое поручение о приёмке и самостоятельных мелких UX-решениях, `codex-task-stroitelnaia-kariera-v2.md`, дополнительное визуальное направление. Приоритет нового поручения позволяет переработать существующие кабинеты без нового цикла утверждения каждой детали. Палитра и доменные права сохранены. Это рабочая реализация, а не утверждение заказчиком окончательного дизайна.

Git проверялся с разовым `-c safe.directory=…`, глобальная конфигурация не менялась.

## Навигация

На desktop — боковая навигация, на mobile до 768 px — нижняя панель тех же разделов. У студента пятый раздел «Профиль», поскольку резюме нужно для отклика; дополнительные функции доступны из компактного раскрытия в шапке содержимого. У работодателя: Главная / Отклики / Объявления / Практиканты / Ещё. У координатора: Задачи / Практики / Студенты / Отчёты / Ещё. У оператора: Задачи / Компании / Объявления / Обращения / Ещё.

Общий каталог модулей удалён. Ещё содержит разделы конкретной роли, а не публичный sitemap. В публичных каталогах используется публичное меню. Демо-инструменты раскрываются отдельно, сброс по-прежнему подтверждается. По уточнению DEC28 в шапке показан только текстовый индикатор роли и текущей подроли работодателя, имя профиля вторично. Смена роли: логотип → приветствие → «Выбрать роль»; демо-инструменты независимы от подписи. На телефоне в шапке виден компактный логотип. Подролевые ссылки фильтрует общий canEmployer; операции продолжают независимо проверять права.

## Состояние, задачи, данные

TaskQueue вычисляет реальные задачи из общего состояния: предложения студенту → возвращённые документы/подготовка → задания; отклики/договор/практиканты компании; согласования/отчёты/исправления вуза; модерация/обращения оператора. Событие уведомления не считается выполненной задачей. В practiceGuidance централизованы статус дела, текущий ответственный, действие роли и следующий этап; ProcessSummary выводит их в начале дела. Добавлены шестиступенчатая шкала и разделы обзора, документов, заданий/отчёта, истории и переписки; на телефоне второстепенные разделы свёрнуты. Query tab открывает нужный раздел. Чек-лист показывает готовность полей каждой стороны и версии обязательных документов. Отправить комплект отправляет только актуальные обязательные черновики одной транзакцией; возврат и устаревшие условия блокируют отправку без частичного сохранения. Индивидуальная отправка сохранена. Завершённое дело ведёт к просмотру итога, а не предлагает продолжение этапа.

В UI скрыты ID экранов, технические пути образовательных полей и university_demo. В объяснении подбора вместо процента — качественная оценка с сохранением исходного алгоритма, полноты и ограничений. Внутренние ссылки используют обычную стрелку. Имя студента добавлено в отклик после разрешённого взаимодействия, чтобы отличать кандидатуры на одно объявление.

Объявление получило необязательные paid/schedule/minCourse/maxCourse; прежние сохранения используют прежние значения по умолчанию. Редактор, фильтр и подбор читают одинаковые поля. Даты вакансии подписаны периодом набора, даты практики — периодом практики. Завершённые наборы доступны через фильтр архива; новый отклик запрещён и интерфейсом, и доменной операцией. Резервы исторических дел не освобождаются произвольно.

Избранное: favoritesByUser[personaId]. Старый favorites без владельца сохраняется для восстановления, но не показывается как личный список. При его наличии есть пояснение с предложением сохранить записи заново. Остальные модули сохранения не сбрасываются; версия envelope не меняется, новое поле необязательное и валидируется.

## Границы

Изображение исходного мобильного референса в доступных файлах не найдено; применены подробно описанные композиционные принципы двух ТЗ и существующие локальные изображения. Физическая клавиатура телефона и системная печать требуют отдельной проверки на устройстве. Разработка не подключает хостинг, внешние сервисы или реальную модель.

## Уточнение DEC29

Блок демонстрации на «Ещё» удалён у всех ролей; оставшиеся группы образуют три колонки на широком экране и одну на узком. Учебная дата, ограничения и подтверждаемый сброс находятся на `/demo/about` по ссылке футера. Возврат на приветствие — логотип.

## Уточнение DEC31 · личное пространство и навигация

Шапка пользовательского сценария содержит 48px аватар (40px на мобильном), имя, роль и траекторию либо подроль работодателя. Подпись «Личный кабинет» и отдельная метка «Демонстрация» сохраняют контекст. Avatar использует инициалы; необязательный photoUrl позволяет заменить их фото без изменения layout, при ошибке загрузки возвращаются инициалы. В профиле аватар 76/64px. Stock-фотографии и генерация лиц не применялись.

Основная навигация — прежние задачи роли, включая просмотр каталогов без подмены меню. Служебная — отдельный nav «Информация и помощь» в футере (/about, /help, /demo/about). Сессия — отдельная отделённая линией группа «Сменить роль» с пояснением сохранности данных. Логотип ведёт домой текущей роли; на welcome по-прежнему обозначает старт. Выбор роли допускает возврат в текущий кабинет без входа заново. Информационные страницы больше не выбирают персонажа автоматически. /about сохраняет оболочку и роль, содержит возврат в кабинет и ссылки на каталоги; Back/Forward возвращают к прежнему месту. Это заменяет прежние указания о возврате на welcome по логотипу.
