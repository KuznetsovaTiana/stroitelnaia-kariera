# Два контура ИИ и подбор

## Контур работодателя: структурированный профиль

В демо это нормализация сведений из тестового образовательного набора в единый шаблон: программа, курс, дисциплины, учебные результаты, проекты, источники. Сам шаблон не требует языковой модели. Имитация ИИ может предложить краткое объяснение подготовки, но каждое утверждение должно ссылаться на имеющееся поле. Источник и дата — учебные, явно обозначенные.

Не превращать факт «изучал дисциплину» в факт «имеет профессиональный стаж» или «владеет инструментом на экспертном уровне». Проект и навык отмечать как вузовский учебный факт либо заявление студента. Окончательное решение принимает работодатель.

## Контур студента: помощник резюме

Минимум четыре ветви: ПТО, проектирование, BIM/ТИМ, сметное дело. Общая последовательность: цель → учебная задача → личный вклад → инструменты → результат → интересующие условия. Пропуск вопроса разрешён. Пустой/непонятный ответ вызывает уточнение или оставляет пробел для редактирования.

Результат строится из ответов текущего пользователя, а не выдаётся одинаковой заготовкой при любых действиях. Показывать предварительный текст и список использованных фактов. Действия: изменить ответ, перегенерировать шаблон, редактировать вручную, принять, отменить. До принятия резюме не изменяется. Для незнакомого свободного ответа — безопасная вставка как пользовательского текста, без притворства, что модель провела глубокий анализ.

Пример: «В учебном проекте подготовил модель перекрытия и проверил пересечения элементов. Использовал …». Не добавлять «снизил затраты на 20%», стаж или названия компаний, если таких данных нет.

Пометка «Имитация ИИ: ответы формируются по демонстрационным правилам». Контрольный переключатель ошибки доступен в демо-инструментах; после ошибки остаются ответы и ручное редактирование.

Будущую отечественную модель подключать через отдельный адаптер. Выбор поставщика, цены, передача данных и серверный ключ — отдельный этап. Никаких API-ключей в клиенте и никакого работающего вызова модели сейчас.

## Подбор: работающие объяснимые правила

Поиск по фильтрам отбирает предложения, а подбор ранжирует допустимые результаты по профилю конкретного студента. Именно персональные факторы и объяснение отличают его от обычного поиска. В первом демо не называть правила нейросетевой оценкой.

Сначала проверить жёсткие ограничения: опубликовано; компания допущена; период, курс и обязательные условия совместимы; у места есть вместимость. Неизвестные данные — `unknown`, а не несоответствие. Несовместимые результаты доступны при явном просмотре всех с пометкой причины, но не лидируют в рекомендациях.

Рабочие веса мягких факторов: программа/профиль 30, подтверждённые учебные навыки 25, проекты 20, регион/готовность к переезду 15, график 10. Для каждого фактора хранить match / partial / mismatch / unknown и evidenceRefs. Для partial использовать 0.5; unknown не считать нулевым умением.

`score = 100 × сумма(weight × matchValue) / сумма(weight известных факторов)`.
Отдельно показывать `coverage = сумма(weight известных факторов) / 100`. Если coverage < 0.5, вместо уверенного процента — «Недостаточно данных», список известных совпадений и отсутствующих сведений. При равном score более полные данные выше, затем стабильный ID. Весовые значения — рабочая настройка, не доказанная модель качества найма.

В обе стороны работает одна функция сравнения studentId + offerId. Вывод: 2–4 факта «Совпало», «Нужно уточнить», «Есть ограничение». В интерфейсе говорить «Совпадение по указанным критериям», не «Вероятность найма». Не учитывать пол, возраст, национальность и другие не относящиеся к задаче характеристики. Не отклонять автоматически.

Контрольные примеры: полное совпадение; неизвестен инструмент; несовместимый период; подходящие навыки при другом регионе; ни одного известного мягкого фактора. Проверить объяснения, а не только число.
