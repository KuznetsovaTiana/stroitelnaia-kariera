# Образовательный профиль, ИИ-помощник и подбор

Актуальная реализация и настройка: [GigaChat](gigachat-integration.md), DEC44 от 17.10.2026. Прямое новое поручение заменяет прежнее ограничение этого документа «никакого работающего вызова модели сейчас».

## Верифицированный образовательный профиль

UniversityDataProvider нормализует существующие данные в StudentVerifiedProfile. Сейчас используется единый учебный mock-набор. Вузовские сведения доступны студенту только для чтения с запросом исправления координатору. Работодатель видит стандартизированную обезличенную часть, отдельно от заявлений студента. Модель не создаёт образовательные факты. Неизвестные сведения не заполняются выдуманными данными.

## ИИ-помощник студента

Два блока: «О себе / профессиональный профиль», «Учебный и практический опыт». Общий frontend service обращается к одной Netlify Function, сервер выбирает prompt по allowlisted action и вызывает GigaChat. История только в состоянии текущей страницы. Результат редактируется и сохраняется только после явного подтверждения, с источником selfReported. Credentials и prompts только на сервере.

Старый мастер фиксированных вопросов и клиентский scriptedAssistant удалены. Сохранена совместимость прежних сохранений и явно подписанный архив операторских примеров. Mock включается только серверным AI_MODE=mock и виден пользователю. При ошибке live fallback на mock запрещён.

## Подбор: работающие объяснимые правила

Поиск по фильтрам отбирает предложения, а подбор ранжирует допустимые результаты по профилю конкретного студента. Именно персональные факторы и объяснение отличают его от обычного поиска. В первом демо не называть правила нейросетевой оценкой.

Сначала проверить жёсткие ограничения: опубликовано; компания допущена; период, курс и обязательные условия совместимы; у места есть вместимость. Неизвестные данные — `unknown`, а не несоответствие. Несовместимые результаты доступны при явном просмотре всех с пометкой причины, но не лидируют в рекомендациях.

Рабочие веса мягких факторов: программа/профиль 30, подтверждённые учебные навыки 25, проекты 20, регион/готовность к переезду 15, график 10. Для каждого фактора хранить match / partial / mismatch / unknown и evidenceRefs. Для partial использовать 0.5; unknown не считать нулевым умением.

`score = 100 × сумма(weight × matchValue) / сумма(weight известных факторов)`.
Отдельно показывать `coverage = сумма(weight известных факторов) / 100`. Если coverage < 0.5, вместо уверенного процента — «Недостаточно данных», список известных совпадений и отсутствующих сведений. При равном score более полные данные выше, затем стабильный ID. Весовые значения — рабочая настройка, не доказанная модель качества найма.

В обе стороны работает одна функция сравнения studentId + offerId. Вывод: 2–4 факта «Совпало», «Нужно уточнить», «Есть ограничение». В интерфейсе говорить «Совпадение по указанным критериям», не «Вероятность найма». Не учитывать пол, возраст, национальность и другие не относящиеся к задаче характеристики. Не отклонять автоматически.

Контрольные примеры: полное совпадение; неизвестен инструмент; несовместимый период; подходящие навыки при другом регионе; ни одного известного мягкого фактора. Проверить объяснения, а не только число.
