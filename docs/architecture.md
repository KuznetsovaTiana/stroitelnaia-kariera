# Техническая основа и публикация

Рабочее инженерное решение, выбранное под демонстрацию с минимальным бюджетом. Это требования к реализации, а не утверждение о уже существующем приложении.

## Состав

React + TypeScript + Vite; маршрутизация на клиенте; локальные шрифты/иконки; статические моковые данные; единое состояние и доменные операции; адаптер localStorage. Конкретные версии выбрать при создании проекта по совместимости и зафиксировать lockfile. Сторонние библиотеки добавлять только по понятной необходимости.

Пример структуры после начала реализации:

```text
src/
  app/             маршруты, общий каркас, роль, провайдер состояния
  components/      кнопки, поля, карточки, таблицы, уведомления
  features/        поиск, профиль, резюме, отклики, практика, документы, аналитика
  domain/          типы, проверки полномочий, переходы, операции и расчёты
  data/            seed, справочники и контрольные примеры
  storage/         чтение, запись, миграции, восстановление
  adapters/        scriptedAssistant, mockImport, documentExport
  styles/          токены и общие стили
```

Компоненты не должны независимо изменять статусы. Например, `acceptPracticeOffer(actorId, applicationId)` проверяет роль, состояние, пересечение практик и места, затем одним обновлением создаёт дело, резерв, событие и уведомление. Интерфейс получает результат или понятную доменную ошибку.

## Что хранить локально

Seed поставляется с приложением. В localStorage сохраняются локальные изменения, пользовательские текстовые поля, настройки, текущая роль, уведомления и события; не фото, PDF или base64. Можно хранить компактное полное состояние при небольшом наборе, но не дублировать большие статические справочники.

Рабочая цель — менее 1 MiB сериализованного изменяемого состояния для сценариев демо; это бюджет проекта, не гарантия квоты любого браузера. Измерять размер JSON при разработке. Ограничить текстовые поля разумной длиной с понятной подсказкой, технический диагностический журнал — например, 1000 последними записями. Доменные события для истории и аналитики не удалять произвольно; при достижении бюджета предложить пользователю сброс демонстрации, сохранив текущую сессию в памяти.

Envelope: `{schemaVersion, seedVersion, revision, savedAt, demoClock, activePersonaId, changes}`. Один ключ `stroitelnaia-kariera:demo:v1` для связанного состояния, чтобы не оставлять половину транзакции в разных ключах. При смене схемы — миграция известных версий; неизвестная версия → предложить восстановление, не молча уничтожать данные.

Ошибки JSON/квоты/запрета записи обрабатывать. Если запись не удалась, действие может остаться в памяти, но явно сообщить «Изменения пока не сохранены на этом устройстве». Дать сброс и повтор. Не утверждать сохранение до успешного setItem.

Сброс удаляет только ключи своего namespace; не вызывать `localStorage.clear()`. Очищение браузера или приватный режим могут убрать сохранённые действия. Для демонстрации это допустимо, исходный набор всегда восстанавливается.

Вкладки одного origin используют общее хранилище. Слушать `storage`: при несовпадении revision предложить загрузить обновления, сохранить несохранённый текст в памяти; не перетирать изменения второй вкладки автоматически. Демонстрация одновременной многопользовательской работы не входит в объём.

## Работа вне чата

После сборки папка `dist` содержит сайт для статического хостинга. Размещение отдаёт HTML, JS, CSS и ресурсы по HTTPS. Устройство пользователя выполняет приложение в браузере. Для опубликованной версии компьютер автора не должен оставаться включённым.

Выбрать hash-маршрутизацию, чтобы прямые переходы и перезагрузка работали без серверной настройки маршрутов. Проверить базовый путь ресурсов при публикации в подпапке. Динамические приватные страницы нельзя рекламировать как защищённые: данные вымышленные и полностью клиентские.

Хостинг пока не выбран. На этапе публикации сравнить актуальные условия статических площадок, лимиты, доступность из нужной сети и приватность исходников. Бесплатность конкретного тарифа заранее не гарантировать. Не покупать домен, не публиковать исходный репозиторий и не создавать внешние интеграции без поручения.

QR содержит только окончательный публичный URL, без localhost, временного preview, токенов и привязки к сеансу ChatGPT. Создать его после проверки URL с телефона и в чистом браузере. Сохранить исходник QR и PNG/SVG, проверить сканирование. Первая загрузка требует интернета; офлайн-режим/PWA не входят в обязательный объём.

## Качество реализации

Семантические формы, явные ошибки, фильтры в URL, безопасный вывод пользовательского текста, ограничение импорта размером и схемой. Никаких ключей API в клиенте, внешних пикселей аналитики или незаявленных сетевых запросов. Разрешённые внешние ссылки открываются как ссылки, а не как обязательные ресурсы приложения.

Проверки до релиза: сборка, типы, базовый lint, небольшой набор тестов доменной логики, один браузерный путь SC02, мобильная ширина 360 px, клавиатура, прямой URL, сохранение и сброс. Среду и фактические результаты записать в progress. Если тест не запускался, это указать.
