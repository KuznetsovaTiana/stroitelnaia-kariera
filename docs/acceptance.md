Пакет задаёт критерии; галочки проставляются только после проверки приложения. Наличие страницы не доказывает выполнение функции. Для каждого результата записать среду, дату, проверявшего и ссылку на дефект при неуспехе.

## Инвентаризация всей карты

Использовать `screens.json` как список 80 ID. На этапе реализации добавить в progress или отдельную таблицу поля `implemented`, `routeChecked`, `actionChecked`, `statesChecked`, `defect`. Каждый ID должен иметь маршрут/диалог и результат из screens.md. Одна общая страница может покрывать несколько ID, если все требуемые состояния и действия доступны.

Минимум для каждого списка — данные и пустая выдача; для каждой формы — успешное сохранение и ошибка валидации; для каждого процесса — допустимый и запрещённый переход. Дополнительные автоматические тесты писать по риску, не для формального количества.

## Автоматические проверки, которые полезны

- Доменный тест: принятие предложения, повторная операция, последнее место и отмена.
- Доменный тест: обязательные документы до начала, возврат новой версии, зачёт.
- Подбор: неизвестные сведения, несовместимый период, одинаковое объяснение в обе стороны.
- Хранилище: сериализация, миграция/неизвестная версия, сброс только своего ключа.
- Один браузерный сценарий SC02 со сменой ролей и перезагрузкой; время демонстрации управляемо.

## Условия завершения

Все обязательные проверки пройдены либо известный дефект явно описан и его влияние согласовано. Дизайн утверждён отдельно. Реальные интеграции, подпись и production-защита не включаются в отчёт как реализованные функции. Ссылка и QR считаются готовыми только после проверки опубликованной сборки.
