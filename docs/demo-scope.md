# Границы демонстрационной версии

Этот документ уточняет исходное ТЗ для ближайшего результата. Требования промышленной платформы сохраняются в исходнике как перспектива.

## Цель и аудитория

Показать жюри чемпионата, как строительные работодатели, студенты и вуз проходят связанный процесс профессионального старта. Рабочее название — «Строительная карьера». До 25.10.2026 предоставить QR-код на демонстрацию. Использовать только вымышленные персональные и корпоративные данные. Единственный вуз в демонстрационном наборе — МГСУ; это контекст сценария, не заявление об официальном партнёрстве.

Платформа в демо предназначена только для студентов. Работодатели могут находиться в Москве, Московской области и других регионах. Посетителю доступна публичная часть. Участие студента неподключённого вуза не предусматривается; настоящей регистрации нет.

## Обязательные продуктовые функции

1. Публичные каталоги практик, вакансий/стажировок, компаний, вузов и профессий/навыков; поиск и работающие фильтры.
2. Образовательная часть профиля по стандартизированному шаблону: программа, курс, дисциплины, учебные результаты, источники и история. Студент не переписывает сведения вуза, а направляет запрос на исправление.
3. Описательная часть резюме: проекты, интересы, навыки, цели. Ручное редактирование и диалоговый помощник в режиме имитации.
4. Подбор в обе стороны с объяснениями по данным. Отделять отсутствие сведений от несоответствия.
5. Отклики и приглашения с понятными состояниями. Переписка после отклика либо принятого приглашения.
6. Организация практики: публикация мест → выбор студентом → решение работодателя → согласование вузом → документы → задания и отчёт → результат.
7. Кабинеты студента, работодателя, координатора вуза и оператора; дополнительные полномочия внутри команды работодателя.
8. Подготовка, просмотр, согласование и скачивание учебных образцов документов.
9. Отраслевые показатели по демонстрационному набору: кадровые запросы, навыки, места практики, воронка. Показатели не представлять как реальные данные рынка.
10. Уведомления, поддержка, модерация, настройки, контрольные ошибки, пустые состояния и сброс демонстрации.

## Глубина реализации

| Модуль | Что действительно работает локально | Что имитируется |
|---|---|---|
| Поиск | Фильтрация, сортировка, сохранение запроса, избранное | Объём рынка представлен небольшим набором |
| Профиль | Источники полей, запрос исправления, решение координатора | Передача и проверка сведений вузом |
| Помощник | Ответы пользователя подставляются в ветвящийся шаблон; результат редактируется | Генеративный диалог с языковой моделью |
| Подбор | Детерминированное сопоставление условий с объяснениями | Интеллектуальная интерпретация сверх правил |
| Практика | Сквозные статусы, назначение руководителя, задания, отчёт, итог | Реальное образовательное сопровождение |
| Документы | Заполнение из сущностей, версии, замечания, скачивание образца | Юридически значимое оформление |
| Проверка компании | Оператор принимает решение по тестовой карточке | Реальные государственные проверки |
| Импорт | Валидация и предпросмотр подготовленного тестового файла | Соединение с информационной системой МГСУ |
| Общение | Локальные сообщения и уведомления между тестовыми ролями | Доставка реальным людям, email/SMS |
| Доступ | Интерфейсные ограничения действий по тестовой роли | Защищённая серверная авторизация |

## Не входит в первую демонстрацию

- Реальная регистрация, пароли, восстановление доступа, оплата и подписки.
- Backend, рабочие интеграции с вузом, кадровыми системами, сервисами подписи и языковой моделью.
- Электронная подпись, даже условная кнопка «подписать» как якобы завершённое юридическое действие.
- Сценарии выпускников и опытных специалистов; самостоятельное добавление студентом компании/места практики; зачёт текущей работы как практики.
- Групповое инициирование практики координатором и совмещение ролей в одном реальном аккаунте.
- Переписка студента с компанией до отклика или принятого приглашения.
- Синхронизация между устройствами, настоящая рассылка, хранение реальных документов.

## Результат для посетителя

Вход по ссылке → короткая пометка о демонстрации → выбор роли/тестового персонажа. Переключатель ролей доступен после явного входа. Первый экран — приветствие, затем отдельный выбор роли и профиля с кнопкой начала; логотип возвращает на приветствие (DEC27). Изменения сохраняются между ролями и перезагрузками в том же браузере при доступном хранилище. «Начать заново» после подтверждения восстанавливает исходный набор. Один посетитель не меняет данные другого устройства; вкладки одного браузерного профиля и адреса используют общее localStorage.
