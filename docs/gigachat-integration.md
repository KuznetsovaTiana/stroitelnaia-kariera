# GigaChat: устройство, запуск и проверка

Обновлено 17.10.2026. Основание — прямое поручение заказчика, DEC44. Base directory Netlify подтверждён заказчиком: `app`. Публикация и подключение платных услуг этим изменением не выполнялись.

## Что изменилось

Существующий маршрут резюме `/student/resumes/:id/assistant` сохранён. Вместо мастера из шести вопросов теперь общий диалог для двух описательных частей. В профиле есть «О себе / профессиональный профиль» и «Учебный и практический опыт». Ручной ввод доступен независимо от API. Перед применением студент проверяет и редактирует результат, затем нажимает «Добавить в профиль». Ответ API сам по себе не изменяет хранилище.

Образовательные факты нормализуются в `StudentVerifiedProfile` через `UniversityDataProvider`. Текущий mock-провайдер читает единый существующий набор и принятые исправления. Пустые достижения и дополнительные дисциплины остаются пустыми; средний балл, уровень образования и стаж не выдумываются. Студент и работодатель используют одну нормализацию. Работодатель до взаимодействия не получает ФИО, контакты и оценки.

Данные студента остаются в `professional` существующего профиля: необязательные `about`, `experienceSummary`, `textSources`. Это selfReported, даже если формулировка подготовлена моделью. Источники: `student`, `ai_assisted`, `mock_assisted`. Старые сохранения принимаются. В резюме добавлено необязательное `experienceSummary`; отклик по-прежнему содержит неизменяемый снимок выбранного резюме.

## Серверный поток

React → `aiService` → `/.netlify/functions/ai` → `aiHandler` → OAuth / GigaChat.

Разрешены только `resume_about`, `resume_experience`, `improve_text`. Произвольные system prompts и дополнительные поля запроса запрещены. Контекст — только программа, курс, названия дисциплин и учебные навыки, без имени, контактов и оценок. Контекст из браузера считается недоверенными данными; он не используется для изменения образовательного источника.

OAuth: `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, Basic Authorization Key, scope и UUID RqUID. Токен кешируется в памяти тёплого экземпляра функции и обновляется перед истечением; после 401 — один повтор с новым токеном. Chat: `POST https://api.giga.chat/v1/chat/completions`. Действующий домен сверён с [официальной справкой REST](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api); OAuth — с [описанием получения токена](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token).

Сервер выбирает русский prompt по action. Модель должна вернуть один JSON-объект question либо result только для запрошенного блока. JSON парсится и валидируется строго; Markdown, произвольный текст, дополнительные verified-поля и усечённый ответ отклоняются. Парсинга «примерного текста» регулярными выражениями нет. Это prompt-контракт, а не гарантия истинности утверждений: необходима проверка студентом.

Ограничения: тело 32 KB, сообщение 2000 символов, до 16 сообщений истории / 12000 символов сериализованной истории, контекст 5000, черновик и итог 3000, ответ поставщика 256 KB, max_tokens=1400. Тайм-аут сервера 22 секунды, клиента 30 секунд. 12 запросов в минуту на IP: ограничение Netlify edge плюс локальный предохранитель экземпляра. Ошибки поставщика, ключи и токены клиенту не возвращаются. Содержимое чата не логируется приложением.

TLS всегда проверяется. Дополнительный корневой PEM можно передать серверной переменной `GIGACHAT_CA_PEM`; он дополняет стандартные доверенные сертификаты. Отключать проверку сертификата нельзя. Источник сертификата — [официальная инструкция](https://developers.sber.ru/docs/ru/gigachat/certificates).

## Настройка Netlify пошагово

1. Откройте Netlify, выберите существующий проект сайта.
2. Откройте **Project configuration → Build & deploy → Continuous deployment → Build settings**. Base directory должен остаться `app`. Действующие Build command и Publish directory не менять. В `app/netlify.toml` добавлен только каталог Functions `netlify/functions` и bundler esbuild.
3. Откройте **Project configuration → Environment variables → Add a variable**. Добавьте переменные из таблицы ниже. Если выбор scope доступен в вашем тарифе, включите **Functions**, для credentials ограничьте scope им. Контекст значений — **Production**; для Deploy Previews задавайте значения отдельно и только при необходимости. Без выбора scope используйте доступную настройку проекта; префикса `VITE_` быть не должно.
4. В кабинете GigaChat API получите **Authorization Key** проекта. Значение `GIGACHAT_CREDENTIALS` — готовая строка Authorization Key (Base64), **без** префикса `Basic `, не access token и не один Client Secret. Никому не отправляйте ключ и не добавляйте его в Git.
5. После сохранения переменных и публикации кода запустите новый deploy через **Deploys → Trigger deploy → Deploy project**. В логе должна собраться функция `ai`. Изменение переменных требует нового deploy — [документация Netlify](https://docs.netlify.com/build/functions/environment-variables/).
6. Откройте `https://ВАШ-ДОМЕН/.netlify/functions/ai`: ожидается JSON `{"mode":"live","available":true}`. Это подтверждает наличие настройки, но не успешную авторизацию у поставщика. Затем проверьте настоящий диалог в профиле.

| Переменная | Значение |
|---|---|
| `AI_MODE` | `live` в production. `mock` только для явно обозначенной проверки без модели |
| `GIGACHAT_CREDENTIALS` | Ваш Authorization Key, серверный секрет |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` для физлица; для соответствующего проекта `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` |
| `GIGACHAT_MODEL` | `GigaChat-2` по умолчанию ([официальные ID](https://developers.sber.ru/docs/ru/gigachat/guides/selecting-a-model)); при необходимости ID доступной вашему проекту модели из API, не рекламное название |
| `GIGACHAT_CA_PEM` | Необязательно: PEM доверенного корневого сертификата по официальной инструкции, если требуется цепочкой TLS. Поддерживаются настоящие переносы строк и буквальные `\n` |
| `AI_ALLOWED_ORIGINS` | Обычно оставить пустым: свой origin разрешён автоматически. При необходимости точные дополнительные origins через запятую, без wildcard |

Секреты не задаются в `netlify.toml`: они должны быть доступны функции во время выполнения. `GET available=true` показывает наличие credentials, а не проверяет их действительность.

## Локальный запуск

Из корня: `cd app`. Скопируйте `.env.example` в `.env.local` (файл игнорируется Git).

Для проверки без внешних запросов укажите в `.env.local`:

```dotenv
AI_MODE=mock
```

Затем `npm.cmd run dev`. Vite предоставляет тот же серверный обработчик на том же endpoint; Netlify CLI не требуется. Режим явно обозначен в диалоге, искусственной задержки нет. Переменные без `VITE_` не публикуются клиенту.

Для live укажите `AI_MODE=live`, свой `GIGACHAT_CREDENTIALS` и подходящие scope/model/CA, затем перезапустите dev-сервер. Если ключ не указан или запрос не прошёл, показывается состояние недоступности, а остальные возможности продолжают работать. Автоматического перехода live → mock нет.

`npm.cmd run preview` обслуживает только статическую сборку: Functions там нет. Для локальной проверки AI используйте `dev`; для production — deploy Netlify с Functions, не загрузку одного каталога dist на статический хостинг.

## Ручная проверка

1. Выберите студента → Профиль. Проверьте сведения вуза и два самостоятельных текстовых блока.
2. Откройте редактор «О себе» → ИИ-помощник. Убедитесь, что режим указан верно. Расскажите об интересах, ответьте на уточнение. Проверьте, что до подтверждения старый текст не меняется.
3. Измените предложенный текст → «Добавить в профиль». Перезагрузите страницу: текст и его источник сохранены, история чата отсутствует.
4. В блоке опыта расскажите о реальной курсовой, личном вкладе и результате. Проверьте отсутствие вымышленных работодателей, инструментов, достижений и превращения учебного опыта в трудовой стаж. При выдуманном факте не принимайте результат; исправьте текст или продолжите диалог.
5. Проверьте ручное заполнение и «Улучшить мой текст». Закройте помощника без применения: профиль не изменяется.
6. Для ошибки временно уберите credentials в локальном live или отключите сеть перед отправкой. Повторная отправка заблокирована во время запроса, ошибка понятна, введённый текст остаётся. В production не меняйте рабочий ключ ради этой проверки.
7. Выберите работодателя → Поиск студентов → кандидат. Подтверждённая часть и информация студента различаются; контакты и оценки не раскрыты. Соответствие объявлению по-прежнему рассчитывается правилами.
8. Проверьте координатора и оператора, смену ролей, возврат логотипом, отклики и ранее отправленные снимки. Повторите профиль и диалог на телефоне.

## Проверки и границы результата

Автоматические тесты проверяют OAuth, кеш и обновление токена, повтор после 401, отсутствие ключа, явный mock, неверный контракт, размер, origin, лимиты, timeout, отсутствие утечки секретов, раздельное хранение источников и неизменность снимков. Это транспортные подстановки, а не реальные вызовы поставщика.

`test:ai` при `AI_MODE=mock` проверяет настоящий локальный handler на 360/390/1440px: оба блока, явное принятие и редактирование, reload, маркировку источника, отсутствие истории в localStorage. Ошибка live и двойной клик проверяются подстановкой ответа в браузере. Скриншоты — `docs/previews/ai-about-*.png`.

Результат 17.10.2026: typecheck, lint, 52 теста / 9 файлов, build, test:ai, test:profile, test:b1, test:b2, test:navigation и test:roles — PASS. Build предупреждает о клиентском чанке >500 KB (538.63 KB / gzip 147.83 KB). test:c не завершён: старый селектор «Тестовая роль» не соответствует текущему входу; навигация четырёх ролей проверена актуальным test:navigation. Полный старый C-аудит этим этапом не перерабатывался. При повторных AI-прогонах подряд возможен штатный 429 из-за 12 запросов/мин: дождитесь следующей минуты либо перезапустите локальный dev-сервер. Лимит production ради тестов не отключается.

Живой вызов GigaChat и deploy не выполнялись: credentials и доступ к настройкам Netlify не предоставлены. После подключения обязательно проверить сеть Netlify → OAuth:9443 / API:443, доверенный сертификат, scope, модель и доступную квоту. Модель может ошибаться даже при запрете в промпте: фактическая достоверность текста требует проверки студентом.

Это публичная демонстрация без настоящей авторизации. Allowlist и ограничения не делают endpoint универсальным прокси, но origin не является удостоверением личности, а лимит по IP не предотвращает распределённое злоупотребление. Перед широким открытием live нужны лимит расходов у поставщика и контроль потребления; для промышленного запуска — настоящая авторизация и распределённые квоты. Credentials не следует выдавать недоверенным preview-веткам. Данные университета, роли, документооборот и переписка остаются демонстрационными. Существующий локальный сценарий не превращался в backend-БД.
